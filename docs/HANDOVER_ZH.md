## 六人分工

| 人员 | 主要负责 | 交付证据 |
|---|---|---|
| 1：代码负责人 | 代码、部署、修复、版本冻结 | 源码、合约地址、部署交易、版本号 |
| 2：业务验收 | 正常流程、取消、超期退款、两种争议结果 | 用例结果、状态截图、交易哈希 |
| 3：合约与权限 | 角色限制、越权、重复支付/提现、资金核对 | 自动测试结果、拒绝原因、资金对账 |
| 4：前端与钱包 | 拒签、账户/网络切换、电脑与真实手机 | 设备/浏览器记录、录屏、问题清单 |
| 5：后端与部署 | 登录、哈希、数据库、在线稳定性 | API 验收、重启证据、部署记录 |
| 6：协调与展示 | 缺陷闭环、报告、slides、视频与提交清单 | 复测记录、贡献说明、演示和链接 |

每位验收人员亲自复测自己提出的问题。所有人都应能解释项目目的、三合约分工、资金流与信任假设；不能只由代码负责人理解系统。

## 免费部署的具体限制

- 网页服务闲置后会休眠，首次唤醒可能需要约 50 秒或更久；演示前提前打开并检查。
- 经授权与个人作业共用 PostgreSQL，使用独立 `sc6113_escrow_group` schema，避免数据表重名。共用连接凭据并不构成权限隔离，两项目共用容量、可用性和到期时间。
- 数据库页面显示 **2026-11-06 到期**。到期前需要导出或迁移数据；本次没有启用付费套餐。
- Render 页面提示 **2026-10-14 09:00（新加坡时间）维护**。避免把唯一一次演示安排在维护窗口，提前录制备份视频。
- 公开仓库方式连接 Render。后续更新源码后应在 Render 选择 **Manual Deploy → Deploy latest commit**，并检查上线版本；不要假定每次推送都会自动部署。

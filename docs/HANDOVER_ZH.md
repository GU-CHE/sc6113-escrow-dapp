## 当前仍需要完成

目前网页显示“Contracts have not been deployed”，这是准确的状态。尚未部署 Sepolia 合约，不能把页面可访问称为全部验收完成。

1. 在安装 MetaMask 的电脑浏览器中打开在线平台。准备一个专用于课程的管理员测试账户，选择 Sepolia，并确保有足够测试 ETH 支付部署 Gas。不要购买真实 ETH 用于本项目。
2. 展开 **Administrator deployment setup**，点击 **Deploy on Sepolia**。你需要亲自在 MetaMask 中确认 4 笔交易：部署 RoleRegistry、部署 EscrowOrders、部署 DisputeResolver、绑定裁决合约。此账户之后就是固定管理员。
3. 每笔交易等待确认。如果中途中断，用同一浏览器、同一账户、同一网络重新点击即可继续已保存的进度；不要清空浏览器数据。
4. 点击 **Download deployment.json**。将这个文件交给代码负责人/本对话。它只有公开地址和区块配置，没有私钥。代码负责人会验证合约绑定与管理员、更新仓库并重新部署 Render。
5. 准备另外两个测试账户，分别注册客户和服务提供者。角色注册后不能改变，管理员账户不能兼任这两种业务角色。可以使用同一个 MetaMask 的不同账户；测试时必须核对当前账户。
6. 完成电脑端正常交易、争议两种裁决、超期退款、权限拒绝、钱包拒签和账户/网络切换验收，保存交易哈希与截图。
7. 用真实手机浏览器检查布局，用 MetaMask 手机内置浏览器检查连接和关键交易。390px 视口模拟已经通过，但不能替代真实手机验收。

无需把私钥、助记词、MetaMask 密码发给代码负责人。钱包确认由持有人自己操作。

## 六人分工

| 人员 | 主要负责 | 交付证据 |
|---|---|---|
| 1：代码负责人 | 代码、部署、修复、版本冻结 | 源码、合约地址、部署交易、版本号 |
| 2：业务验收 | 正常流程、取消、超期退款、两种争议结果 | 用例结果、状态截图、交易哈希 |
| 3：合约与权限 | 角色限制、越权、重复支付/提现、资金核对 | 自动测试结果、拒绝原因、资金对账 |
| 4：前端与钱包 | 拒签、账户/网络切换、电脑与真实手机 | 设备/浏览器记录、录屏、问题清单 |
| 5：后端与部署 | 登录、哈希、数据库、在线稳定性 | API 验收、重启证据、部署记录 |
| 6：协调与展示 | 缺陷闭环、报告、slides、视频与提交清单 | 复测记录、贡献说明、演示和链接 |

每位验收人员亲自复测自己提出的问题。所有人都应能解释项目目的、三合约分工、资金流与信任假设；不能只由代码负责人理解系统。

## 免费部署的具体限制

- 网页服务闲置后会休眠，首次唤醒可能需要约 50 秒或更久；演示前提前打开并检查。
- 经授权与个人作业共用 PostgreSQL，使用独立 `sc6113_escrow_group` schema，避免数据表重名。共用连接凭据并不构成权限隔离，两项目共用容量、可用性和到期时间。
- 数据库页面显示 **2026-11-06 到期**。到期前需要导出或迁移数据；本次没有启用付费套餐。
- Render 页面提示 **2026-10-14 09:00（新加坡时间）维护**。避免把唯一一次演示安排在维护窗口，提前录制备份视频。
- 公开仓库方式连接 Render。后续更新源码后应在 Render 选择 **Manual Deploy → Deploy latest commit**，并检查上线版本；不要假定每次推送都会自动部署。
